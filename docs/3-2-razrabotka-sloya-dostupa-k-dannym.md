# 3.2 Разработка слоя доступа к данным

Для реализации слоя доступа к данным была выбрана библиотека **Sequelize ORM**. Спроектированная база данных содержит **13 сущностей**: Role, User, UserRole, Course, CourseStaff, CourseReview, Lesson, Exercise, Enrollment, Certificate, Submission, Favorite, Reminder.

Каждая сущность реализована с помощью модели Sequelize. **Модель (Model)** – это описание структуры таблицы, которое определяет, какие поля и их типы данных будут присутствовать в таблице базы данных PostgreSQL. Связи между моделями описаны через внешние ключи и методы ассоциаций (`hasOne`, `belongsTo`, `hasMany`, `belongsToMany`).

Структура базы данных представлена на рисунке 3.1.

**Рисунок 3.1 – Структура базы данных**

---

Сущность **Roles** предназначена для хранения справочника платформенных ролей пользователей. Для представления этой информации использованы такие атрибуты, как:

- code – код роли (STUDENT, TEACHER, ADMIN); первичный ключ справочника.

Сущность **Users** предназначена для хранения информации о пользователях платформы. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер пользователя;
- email – электронная почта пользователя (уникальная);
- password_hash – хешированный пароль пользователя;
- name – имя пользователя;
- created_at – дата и время регистрации;
- updated_at – дата и время последнего изменения записи.

Сущность **UserRoles** предназначена для хранения назначенных пользователям платформенных ролей (связь «многие-ко-многим» между Users и Roles). Для представления этой информации использованы такие атрибуты, как:

- user_id – идентификационный номер пользователя (внешний ключ на Users, часть составного первичного ключа);
- role_code – код роли (внешний ключ на Roles, часть составного первичного ключа).

Сущность **Courses** предназначена для хранения информации об учебных курсах. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер курса;
- title – название курса;
- description – описание курса;
- language – изучаемый язык;
- level – уровень сложности курса;
- published – признак публикации курса в каталоге;
- rating_average – средний рейтинг курса (кэш для сортировки каталога);
- created_at – дата создания курса;
- updated_at – дата последнего изменения курса.

Сущность **CourseStaff** предназначена для хранения информации о составе команды курса. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер записи о назначении;
- course_id – идентификационный номер курса (внешний ключ на Courses);
- user_id – идентификационный номер пользователя (внешний ключ на Users);
- staff_role – роль участника в штате курса (TEACHER, AUTHOR, METHODIST, CURATOR);
- created_at – дата назначения на роль.

Сущность **CourseReviews** предназначена для хранения отзывов студентов о курсах. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер отзыва;
- user_id – идентификационный номер автора отзыва (внешний ключ на Users);
- course_id – идентификационный номер курса (внешний ключ на Courses);
- rating – оценка курса от 1 до 5;
- comment – текст отзыва;
- created_at – дата создания отзыва;
- updated_at – дата изменения отзыва.

Сущность **Lessons** предназначена для хранения уроков в составе курса. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер урока;
- course_id – идентификационный номер курса (внешний ключ на Courses);
- title – название урока;
- sort_order – порядок урока в курсе;
- content – учебный контент урока.

Сущность **Exercises** предназначена для хранения упражнений в составе урока. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер упражнения;
- lesson_id – идентификационный номер урока (внешний ключ на Lessons);
- title – название упражнения;
- type – тип упражнения;
- payload – данные упражнения в формате JSONB.

Сущность **Enrollments** предназначена для хранения информации о записи студентов на курсы. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер записи на курс;
- user_id – идентификационный номер студента (внешний ключ на Users);
- course_id – идентификационный номер курса (внешний ключ на Courses);
- progress – прогресс прохождения курса в процентах (от 0 до 100);
- created_at – дата записи на курс;
- updated_at – дата обновления прогресса.

Сущность **Certificates** предназначена для хранения выданных сертификатов о прохождении курса. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер сертификата;
- enrollment_id – идентификационный номер записи на курс (внешний ключ на Enrollments, уникальный);
- document_number – уникальный номер документа сертификата;
- issued_at – дата и время выдачи сертификата.

Сущность **Submissions** предназначена для хранения ответов пользователей на упражнения. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер отправки ответа;
- user_id – идентификационный номер пользователя (внешний ключ на Users);
- exercise_id – идентификационный номер упражнения (внешний ключ на Exercises);
- score – балл за выполнение упражнения;
- payload – данные ответа в формате JSONB;
- created_at – дата и время отправки ответа.

Сущность **Favorites** предназначена для хранения избранных курсов пользователей. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер записи;
- user_id – идентификационный номер пользователя (внешний ключ на Users);
- course_id – идентификационный номер курса (внешний ключ на Courses);
- created_at – дата добавления курса в избранное.

Сущность **Reminders** предназначена для хранения напоминаний пользователей о занятиях. Для представления этой информации использованы такие атрибуты, как:

- id – идентификационный номер напоминания;
- user_id – идентификационный номер пользователя (внешний ключ на Users);
- course_id – идентификационный номер курса (внешний ключ на Courses, опциональный);
- title – заголовок напоминания;
- remind_at – дата и время срабатывания напоминания;
- delivered_at – дата и время доставки уведомления;
- email_sent_at – дата и время отправки электронного письма;
- acknowledged_at – дата и время подтверждения напоминания пользователем;
- created_at – дата создания напоминания.

Связи между сущностями реализованы через внешние ключи и описаны в файле `server/db/models/index.js`. Sequelize автоматически создаёт внешние ключи на основе описанных ассоциаций, обеспечивая целостность данных и каскадное удаление связанных записей.
