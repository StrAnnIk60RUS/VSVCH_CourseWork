# 3.4 Разработка клиентской части

Клиентская часть платформы VSVH Languages разрабатывалась с помощью библиотеки React (версия 19), Redux Toolkit и React Router. Приложение реализовано как одностраничное (SPA) на TypeScript, собирается с помощью Webpack и обращается к REST API серверной части (раздел 3.3) через библиотеку Axios. Интерфейс поддерживает два языка — русский и английский.

Структура клиентской части представлена на рисунке 3.3.

## Структура папки client/src

Главная папка src представлена следующими файлами: App.tsx – главный компонент приложения, управляющий маршрутизацией (BrowserRouter, Routes), общей оболочкой страниц (AppChrome — шапка и подвал), восстановлением сессии по JWT при загрузке, опросом срабатывающих напоминаний (интервал 30 секунд) и отображением всплывающих уведомлений о просроченных напоминаниях; styles/global.css – глобальные стили и CSS-переменные для реализации светлой и тёмной темы (атрибут data-theme на элементе document.documentElement), а также utility-классы Tailwind CSS; main.tsx – точка входа в приложение, где происходит инициализация React через ReactDOM.createRoot (в режиме React.StrictMode), подключение Redux Provider, импорт глобальных стилей и рендеринг компонента App.

Папка api содержит сервисы для выполнения HTTP-запросов к серверной части. Файл http.ts настраивает экземпляр Axios с базовым URL (http://localhost:4000/api или переменная окружения API_URL) и перехватчиком запросов: при наличии JWT-токена в localStorage добавляет заголовок Authorization: Bearer …. Перехватчика ответов с автоматическим выходом при ошибке 401 нет. Остальные файлы экспортируют асинхронные функции для соответствующих групп эндпоинтов: authApi.ts, coursesApi.ts, learningApi.ts, favoritesApi.ts, profileApi.ts, remindersApi.ts, teacherApi.ts, reportsApi.ts. Функция getApiError извлекает текст ошибки из ответа сервера для отображения пользователю.

Папка components содержит переиспользуемые компоненты. Компонент AppNav (подпапка layout) отображает шапку сайта с логотипом, навигационным меню (главная, каталог курсов или «Мои курсы» для преподавателя, «Моё обучение» с подпунктами для студента, напоминания, аналитика для преподавателя — состав зависит от роли), мобильным меню, выпадающим меню «Настройки» (смена темы и языка), кнопками входа и регистрации или именем пользователя с выходом. Компонент AppFooter отображает копирайт. Компоненты PageShell и SectionCard задают единый каркас заголовка и секций страниц. Компонент NavigationUp выводит ссылки на родительские разделы (например, «← Каталог», «← Главная»). Компонент RequireAuth (подпапка auth) проверяет авторизацию пользователя и при необходимости роль (STUDENT или TEACHER), перенаправляя неавторизованных на страницу входа; отдельной проверки роли администратора в клиенте нет (роль ADMIN в интерфейсе не используется).

Папка pages содержит компоненты web-страниц; каждая страница расположена в отдельной подпапке (HomePage, CoursesPage, LoginPage и т.д.). Внутри подпапки: тонкая обёртка Page.tsx (подключение стилей), components/PageContent.tsx (разметка и логика), styles/страницы.css (локальные стили).

Папка store содержит Redux-хранилище. Файл index.ts конфигурирует store с редьюсером appSlice; типизированные хуки — в store/hooks.ts. Слайс appSlice определяет начальное состояние и синхронные действия (reducers) для UI: название приложения, тему (light / dark), язык интерфейса (ru / en) и флаг authChecked. Асинхронные действия (createAsyncThunk) и доменные слайсы (курсы, записи, отправки) в проекте не используются — эти данные загружаются на страницах через useState и useEffect. Текущий пользователь и сессия для маршрутов хранятся в AuthSessionContext (см. hooks/useAuthSession.ts), а не в Redux.

Папка hooks содержит useAuthSession — доступ к AuthSessionContext: текущий пользователь (user), флаг authChecked и функция setAuthenticatedUser; useI18n — доступ к строкам локализации из constants/i18n.ts.

Папки constants, types и utils содержат ключи localStorage (storage.ts, в том числе vsvh:token для JWT), справочники языков и уровней курсов (courseOptions.ts), TypeScript-типы DTO (domain.ts) и утилиту readAccessToken (session.ts). Отчёты PDF и DOCX на клиенте не формируются — они запрашиваются с сервера через reportsApi и скачиваются как бинарные файлы (responseType: blob).

JWT-токен сохраняется в localStorage под ключом vsvh:token. При успешном входе или регистрации токен записывается в обработчике onSubmit формы; при старте приложения App.tsx вызывает GET /api/auth/me для восстановления сессии.

В соответствии с техническим заданием разработано 16 web-страниц (маршрутов React Router): 2 страницы аутентификации, остальные — каталог, обучение, кабинет студента и кабинет преподавателя.

Логика работы страницы «Регистрация»:
	маршрут /register; компонент RegisterPage.tsx, логика — RegisterPageContent.tsx;
	пользователь заполняет поля формы: имя, email, пароль, выбирает роль (студент или преподаватель) в выпадающем списке;
	нажимает кнопку «Зарегистрироваться»;
	из клиентского кода уходит HTTP-запрос POST /api/auth/register (функция registerUser в authApi.ts, обработчик onSubmit в RegisterPageContent.tsx);
	backend создаёт пользователя и запись роли, возвращает объект пользователя и JWT-токен;
	JWT-токен сохраняется в localStorage (STORAGE_KEYS.token), пользователь записывается в контекст через setAuthenticatedUser;
	в случае ошибки (email уже занят, некорректные данные) пользователь видит сообщение об ошибке под формой (функция getApiError);
	в случае успешной регистрации пользователь автоматически авторизуется и перенаправляется на /courses (для роли TEACHER в App.tsx срабатывает редирект на /teacher/courses).

Логика работы страницы «Вход»:
	маршрут /login; компонент LoginPage.tsx, логика — LoginPageContent.tsx;
	пользователь вводит email и пароль;
	нажимает кнопку «Войти»;
	из клиентского кода уходит HTTP-запрос POST /api/auth/login (функция loginUser в authApi.ts, обработчик onSubmit в LoginPageContent.tsx);
	backend проверяет учётные данные, возвращает объект пользователя и JWT-токен;
	JWT-токен сохраняется в localStorage, сессия обновляется в контексте;
	в случае ошибки (неверный email или пароль) пользователь видит сообщение об ошибке;
	в случае успешного входа выполняется переход на /courses (для преподавателя — далее редирект на /teacher/courses).

Логика работы страницы «Главная»:
	маршрут /; компонент HomePage.tsx, логика — HomePageContent.tsx; доступна всем пользователям;
	для гостей и студентов при загрузке отправляется запрос GET /api/courses с параметрами page=1, limit=4, sort=popularity, order=desc (функция getCourses в coursesApi.ts) — отображаются популярные курсы;
	для пользователя с ролью TEACHER блок популярных курсов не загружается; кнопки призыва ведут в кабинет преподавателя (/teacher/courses);
	отображается приветственный блок (hero), описание платформы и блок «Как это работает»;
	для гостей и студентов доступны быстрые ссылки на каталог с предустановленными query-параметрами (популярные, новые, английский язык, уровень beginner);
	для авторизованного студента основные кнопки ведут в «Моё обучение» (/me/learning), для гостя — в регистрацию или каталог;
	при клике на карточку курса пользователь переходит на /courses/:courseId.

Логика работы страницы «Каталог курсов»:
	маршрут /courses; компонент CoursesPage.tsx, логика — CoursesPageContent.tsx;
	пользователи с ролью TEACHER перенаправляются на /teacher/courses (логика в App.tsx);
	при загрузке и при изменении фильтров отправляется запрос GET /api/courses (функция getCourses);
	query-параметры: язык (language), уровень (level), минимальный рейтинг (minRating), поиск (search), сортировка (sort: createdAt / popularity / rating), порядок (order), страница (page), лимит (limit=8);
	выбранные фильтры, сортировка и номер страницы сохраняются в localStorage (catalogFilters, catalogSort, catalogPage);
	курсы отображаются карточками с названием, описанием, языком, уровнем, числом уроков и средним рейтингом;
	пользователь может сбросить фильтры и переключать страницы пагинации;
	при клике на карточку — переход на страницу курса.

Логика работы страницы «Карточка курса»:
	маршрут /courses/:courseId; компонент CourseDetailPage.tsx; просмотр доступен всем, запись и избранное — авторизованному студенту;
	при загрузке отправляется запрос GET /api/courses/:courseId (функция getCourseById);
	отображаются описание, язык, уровень, рейтинг и список уроков с индикатором прогресса в процентах (для записанного студента);
	для студента дополнительно загружаются записи (GET /api/enrollments), избранное (GET /api/favorites) и собственный отзыв (GET /api/courses/:courseId/review/me);
	кнопка «Записаться» отправляет POST /api/enrollments (enrollToCourse); «Отписаться» — DELETE /api/enrollments/:courseId;
	кнопка избранного — POST /api/favorites или DELETE /api/favorites/:courseId;
	форма отзыва (оценка 1–5, комментарий) доступна студенту после записи на курс; отправка — POST /api/courses/:courseId/review (upsertCourseReview);
	при клике на урок — переход на /courses/:courseId/lessons/:lessonId; ссылка «Все отзывы» — на /courses/:courseId/reviews.

Логика работы страницы «Отзывы о курсе»:
	маршрут /courses/:courseId/reviews; компонент CourseReviewsPage.tsx; доступна всем;
	при загрузке параллельно выполняются GET /api/courses/:courseId и GET /api/courses/:courseId/reviews;
	отображается список отзывов с оценкой, текстом, датой и именем автора;
	кнопка «Назад» возвращает на карточку курса.

Логика работы страницы «Урок»:
	маршрут /courses/:courseId/lessons/:lessonId; компонент LessonPage.tsx, логика — LessonPageContent.tsx; доступ только авторизованным (RequireAuth);
	загружаются данные курса (GET /api/courses/:courseId), урока (GET /api/courses/:courseId/lessons/:lessonId), упражнений (GET …/exercises), записей пользователя и история отправок (GET /api/submissions);
	отображается текст урока и навигация по урокам курса;
	упражнения с полем ввода ответа и отправка на проверку доступны только студенту с активной записью на курс; если студент не записан, показывается предложение записаться (POST /api/enrollments);
	при отправке ответа уходит POST /api/submissions (функция submitExercise с полями exerciseId, answer);
	backend проверяет ответ, возвращает балл, флаг правильности и обновлённый прогресс курса;
	на экране отображается результат (верно/неверно, балл) и сохранённые лучшие ответы по упражнениям урока.

Логика работы страницы «Моё обучение»:
	маршрут /me/learning; компонент MyLearningPage.tsx; доступ только студенту (RequireAuth roles={['STUDENT']});
	при загрузке отправляется GET /api/enrollments (функция getEnrollments);
	отображается список записанных курсов с прогрессом в процентах, данными курса и сведениями о сертификате (если выдан);
	кнопка «Отписаться» — DELETE /api/enrollments/:courseId;
	при прогрессе 100 % доступна кнопка «Получить сертификат» — POST /api/certificates (issueCertificate);
	для выданного сертификата доступно скачивание PDF — GET /api/certificates/:id/pdf (downloadCertificatePdf);
	переход на карточку курса или урок по ссылкам в списке.

Логика работы страницы «Избранное»:
	маршрут /me/favorites; компонент FavoritesPage.tsx; доступен любому авторизованному пользователю (RequireAuth без проверки роли), пункт меню отображается только студенту в AppNav;
	при загрузке — GET /api/favorites (getFavorites);
	курсы отображаются списком с языком, уровнем и кнопками «Открыть» / «Удалить»;
	удаление — DELETE /api/favorites/:courseId (removeFavorite).

Логика работы страницы «Прогресс и статистика»:
	маршрут /me/progress; компонент ProgressPage.tsx; доступ только студенту;
	при загрузке — GET /api/submissions (getSubmissions) — история ответов на упражнения;
	отображаются упражнение, урок, курс, балл и дата каждой отправки;
	кнопки скачивают отчёт о прогрессе с сервера: GET /api/reports/student-progress.pdf или .docx (downloadReport);
	кнопка отправки отчёта на email — POST /api/reports/send-email (sendReportEmail); при отсутствии SMTP сервер возвращает demo-режим.

Логика работы страницы «Напоминания»:
	маршрут /me/reminders; компонент RemindersPage.tsx; доступен авторизованному пользователю;
	при загрузке — GET /api/reminders;
	пользователь создаёт напоминание (заголовок, дата/время) — POST /api/reminders;
	редактирование — PUT /api/reminders/:id; удаление — DELETE /api/reminders/:id;
	в корневом App.tsx каждые 30 секунд опрашиваются напоминания; просроченные показываются всплывающим блоком в правом верхнем углу; закрытие удаляет напоминание через API.

Логика работы страницы «Профиль»:
	маршрут /me/profile; компонент ProfilePage.tsx; доступен авторизованному пользователю;
	при загрузке — GET /api/users (getProfile);
	отображаются email (только чтение) и редактируемое имя;
	сохранение имени — PUT /api/users (updateProfileName);
	кнопка «Сбросить настройки интерфейса» очищает сохранённые фильтры каталога, тему и язык в localStorage (clearUiStorage);
	смена пароля, email и аватар в текущей версии клиента не реализованы.

Логика работы страницы «Курсы преподавателя»:
	маршрут /teacher/courses; компонент TeacherCoursesPage.tsx; доступ только преподавателю;
	при загрузке — GET /api/teacher/courses (getTeacherCourses);
	отображается список курсов, где пользователь назначен TEACHER, с агрегатами: уроки, записи, отзывы, рейтинг, статус публикации;
	кнопка «Создать курс» ведёт на /teacher/courses/new;
	клик по курсу — переход на /teacher/courses/:courseId.

Логика работы страницы «Новый курс»:
	маршрут /teacher/courses/new; компонент TeacherCourseNewPage.tsx; доступ только преподавателю;
	пользователь заполняет название, описание, язык и уровень;
	отправляется POST /api/courses (createCourse); сервер создаёт курс и назначает автора в штат TEACHER;
	после успеха — перенаправление на страницу управления созданным курсом.

Логика работы страницы «Управление курсом»:
	маршрут /teacher/courses/:courseId; компонент TeacherCourseManagePage.tsx, логика — TeacherCourseManagePageContent.tsx, хук useTeacherCourseManage.ts; доступ преподавателю с правом ведения курса;
	при загрузке — GET /api/teacher/courses/:courseId, список студентов (GET …/students), упражнения по урокам;
	секция «Содержание курса»: редактирование метаданных (PUT /api/courses/:courseId) и CRUD уроков и упражнений (POST/PUT/DELETE);
	секция «Студенты»: таблица с прогрессом и активностью, фильтр по статусу, сортировка; экспорт CSV — GET /api/teacher/courses/:courseId/students.csv;
	секция «Отчёты»: скачивание сводного отчёта PDF/DOCX и отправка на email через reportsApi.

Логика работы страницы «Аналитика преподавателя»:
	маршрут /teacher/analytics; компонент TeacherAnalyticsPage.tsx; доступ только преподавателю;
	загружается список курсов преподавателя (GET /api/teacher/courses);
	при выборе курса и периода (7 / 30 / 90 дней) — GET /api/reports/teacher-analytics (getTeacherAnalytics);
	отображаются KPI (число студентов, средний прогресс, активные, «в зоне риска»), диаграммы (библиотека recharts), таблица студентов;
	доступны экспорт CSV списка студентов, PDF/DOCX сводного отчёта и отправка отчёта по email.

Логика обработки неизвестного маршрута:
	при переходе на несуществующий URL срабатывает catch-all-маршрут в App.tsx;
	выполняется перенаправление на главную страницу (/), отдельная страница ошибки не отображается.

## Защита маршрутов, состояние и локализация

Маршруты, требующие авторизации, обёрнуты в RequireAuth: до завершения проверки сессии показывается индикатор загрузки; гости перенаправляются на /login; при указании roles проверяется роль STUDENT или TEACHER (иначе редирект на /). Данные user и authChecked берутся из AuthSessionContext, а не из Redux. Клиентские проверки дублируют серверные ограничения (раздел 3.3).

JWT добавляется к запросам перехватчиком Axios; при ошибке восстановления сессии токен удаляется в App.tsx. Тема и язык — в appSlice и localStorage, синхронизируются с document.documentElement (data-theme, lang). Строки интерфейса — в constants/i18n.ts.
