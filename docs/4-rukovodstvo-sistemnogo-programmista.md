# 4 Руководство системного программиста

Данный раздел описывает развёртывание и запуск веб-платформы **VSVH** (изучение иностранных языков) на локальном компьютере проверяющего. Инструкция соответствует структуре репозитория: монорепозиторий с клиентом (`client/`), сервером (`server/`) и единой установкой зависимостей через npm workspaces.

---

## 4.1. Требования к программному и техническому обеспечению

Для развёртывания и запуска приложения необходимо следующее программное обеспечение:

| Компонент | Версия | Назначение | Ссылка |
|-----------|--------|------------|--------|
| **Node.js** | 18.0 или выше (рекомендуется LTS 20+) | Среда выполнения API и сборки клиента | https://nodejs.org |
| **npm** | поставляется с Node.js | Установка зависимостей и запуск скриптов | — |
| **PostgreSQL** | 14.0 или выше | СУБД приложения | https://www.postgresql.org/download/ |
| **pgAdmin 4** | актуальная | Импорт SQL-дампа базы данных | https://www.pgadmin.org/download/ |
| **Веб-браузер** | актуальная | Google Chrome, Mozilla Firefox или Microsoft Edge | — |

Для редактирования кода и работы с терминалом рекомендуется **Visual Studio Code** (https://code.visualstudio.com).

Минимальные аппаратные требования: 64-разрядная ОС (Windows 10/11, Linux или macOS), не менее 4 ГБ ОЗУ, свободное место на диске порядка 500 МБ (Node.js, PostgreSQL, зависимости проекта).

---

## 4.2. Состав поставки

Программный комплекс поставляется в виде исходного кода в репозитории (клонирование с GitHub) или архива на носителе. Корневая папка проекта — `VSVH/`.

| Каталог / файл | Назначение |
|----------------|------------|
| `client/` | Клиентское приложение (React, TypeScript, Webpack) |
| `server/` | Серверное API (Node.js, Express, Sequelize) |
| `server/database/dumps/vsvh_languages.sql` | SQL-дамп базы данных (схема и демонстрационные данные) |
| `server/env.example` | Образец файла конфигурации сервера |
| `docs/` | Документация, в том числе тестовые учётные записи |
| `package.json` | Корневой манифест npm workspaces (`client`, `server`) |

После установки зависимостей и импорта дампа приложение доступно по адресу клиента **http://localhost:5173**, API — **http://localhost:4000**.

## 4.3. Настройка подключения к базе данных

Перед запуском приложения необходимо настроить подключение к PostgreSQL.

1. В каталоге `server` скопируйте файл `env.example` в файл `.env` (файл `.env` в систему контроля версий не включается).
2. Отредактируйте `server/.env`, указав параметры, соответствующие вашей установке PostgreSQL.

В проекте используется единая строка подключения **`DATABASE_URL`** (отдельные переменные `DB_USER` и `DB_PASSWORD` не применяются).

Структура файла `server/.env` представлена на рисунке 4.1 (в пояснительной записке — скриншот или листинг файла).

**Рисунок 4.1 – Параметры файла `server/.env`**

| Переменная | Назначение | Пример значения |
|------------|------------|-----------------|
| `DATABASE_URL` | Строка подключения к PostgreSQL | `postgresql://postgres:ваш_пароль@localhost:5432/vsvh_languages?schema=public` |
| `JWT_SECRET` | Секретный ключ для подписи JWT | произвольная длинная строка |
| `JWT_EXPIRES_IN` | Срок действия access-токена | `7d` |
| `PORT` | Порт HTTP-сервера API | `4000` |
| `CLIENT_ORIGIN` | Разрешённый origin фронтенда (CORS) | `http://localhost:5173` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | Почта для отправки отчётов (опционально) | можно оставить пустыми для локальной проверки без e-mail |

Пример минимальной конфигурации:

```env
DATABASE_URL="postgresql://postgres:ваш_пароль@localhost:5432/vsvh_languages?schema=public"
JWT_SECRET="change-me-in-production"
JWT_EXPIRES_IN=7d
PORT=4000
CLIENT_ORIGIN="http://localhost:5173"
```

Имя базы данных в `DATABASE_URL` должно совпадать с именем БД, созданной при импорте дампа: **`vsvh_languages`**.

## 4.4. Алгоритм установки программного обеспечения на локальный компьютер

1. Установить **Node.js** (18+) и **PostgreSQL** (14+). При необходимости установить **pgAdmin 4**.
2. Получить исходный код проекта: клонировать репозиторий с GitHub (`git clone …`) или распаковать архив в папку, например `C:\University\VSVH`.
3. Открыть **корневую** папку проекта `VSVH` в Visual Studio Code или в терминале (PowerShell, cmd, bash).
4. Установить зависимости **одной командой из корня** (охватывает и клиент, и сервер за счёт npm workspaces):

   ```bash
   npm install
   ```

5. В **pgAdmin 4** (или через `psql`) создать пустую базу данных с именем **`vsvh_languages`** (кодировка UTF8).
6. Импортировать SQL-дамп базы данных:
   - файл: `server/database/dumps/vsvh_languages.sql`;
   - в pgAdmin: правый щелчок по БД `vsvh_languages` → **Query Tool** → **Open File** → выбрать `vsvh_languages.sql` → **Execute** (F5);
   - из командной строки (при наличии `psql` в PATH):

     ```bash
     psql -U postgres -d vsvh_languages -f server/database/dumps/vsvh_languages.sql
     ```

7. Скопировать `server/env.example` в `server/.env` и в переменной **`DATABASE_URL`** указать логин, пароль и хост вашего PostgreSQL (см. п. 4.3).
8. **Не выполнять** команду `npm run db:seed`, если дамп `vsvh_languages.sql` импортирован полностью: он уже содержит схему и демонстрационные данные. Повторный сид приведёт к ошибкам дублирования записей.
9. Запустить **серверную часть** (первый терминал):

   ```bash
   cd server
   npm start
   ```

   В консоли должно появиться сообщение: `API http://localhost:4000`.

10. Запустить **клиентскую часть** (второй терминал):

    ```bash
    cd client
    npm start
    ```

    Запускается webpack dev server (порт **5173**).

11. Открыть веб-браузер и перейти по адресу: **http://localhost:5173**.

12. Дополнительная проверка API: в браузере или через curl выполнить запрос `GET http://localhost:4000/api/health` — в ответе должно быть подтверждение работоспособности сервера.

### Альтернативный запуск (один терминал)

Из **корня** репозитория можно одновременно запустить клиент и сервер:

```bash
npm run dev
```

При этом клиент доступен на http://localhost:5173, API — на http://localhost:4000. Для проверки по методичке предпочтителен вариант с двумя терминалами (`npm start` в `server/` и `client/`).

### Восстановление БД без дампа (для разработчиков)

Если дамп недоступен, схему и данные можно получить миграциями и сидом из корня проекта:

```bash
npm run db:migrate
npm run db:seed
```

Подробнее — в [`README.md`](../README.md) и [`DATABASE.md`](DATABASE.md).

## 4.6. Типичные ошибки и устранение

| Симптом | Возможная причина | Действие |
|---------|-------------------|----------|
| `listen EADDRINUSE` при запуске | Порт 4000 или 5173 занят предыдущим процессом | Завершить другой экземпляр `npm run dev` / `npm start` |
| Ошибка подключения к БД при старте API | Неверный `DATABASE_URL` или PostgreSQL не запущен | Проверить службу PostgreSQL, логин/пароль в `.env` |
| Пустой каталог курсов после входа | Дамп не импортирован или импорт в другую БД | Повторить шаг 6 для БД `vsvh_languages` |
| Ошибки при `npm run db:seed` после дампа | Данные уже загружены дампом | Не запускать сид (п. 4.4, шаг 8) |
| Страница не открывается | Обращение к порту 3000 вместо 5173 | Использовать **http://localhost:5173** |
| CORS / блокировка запросов с клиента | `CLIENT_ORIGIN` не совпадает с URL клиента | В `.env` указать `http://localhost:5173` |
